# Fact Lens 피벗 결정안

작성 시각: 2026-08-16 20:35 KST

## 결론

현재 `일반 뉴스 팩트체크 확장 프로그램` 정의는 중단합니다. 기존 코드 전체를 버리지는 않고 기사 추출, 문장 위치 매칭, 인라인 하이라이트, Gemini Interactions 호출, 빌드·테스트 기반만 재사용합니다.

추천 피벗은 **과학·건강 뉴스의 보도 문장과 원 논문의 연구 설계를 비교하는 왜곡 감사 도구**입니다. 임시 이름은 `원문대로`입니다.

> 과학·건강 뉴스의 주장을 원 논문의 대상·표본·연구 유형·상관/인과·한계 문장과 나란히 비교하여, 논문보다 강해진 표현만 기사 안에서 표시합니다.

## 왜 이 방향인가

### 제외한 방향

1. 일반 AI 팩트체크
   - Free Fact Checker, Facticity, Aletheia 등 직접 대체재가 있습니다.
2. 기사 1차 출처 계보 추적
   - StoryTracer가 같은 사용자 작업을 수행하며 PaperTrail은 주장-근거 단위 매핑을 연구했습니다.
3. KOSIS 기반 뉴스 수치 검증
   - 공개 저장소 `clafact`가 AI 기반 뉴스 수치 검증과 KOSIS 연동을 이미 제시합니다.

### 추천 방향의 경계

- 뉴스가 참인지 거짓인지 판정하지 않습니다.
- 매체 전체 신뢰도나 편향 점수를 만들지 않습니다.
- 뉴스가 인용한 연구보다 표현을 강하게 바꿨는지만 확인합니다.
- 검색 범위는 과학·건강 기사와 연결 가능한 원 논문으로 제한합니다.
- 원 논문을 찾지 못하거나 근거 문장을 연결하지 못하면 `검토 불가`로 끝냅니다.

이번 제한 검색에서 과학 보도 과장 탐지 연구와 건강 팩트체크 도구는 확인됐지만, `한국어 뉴스 문장 → 해당 원 논문 → 연구 설계 경계 → 기사 안의 과장 유형 표시`를 같은 흐름으로 제공하는 직접 소비자용 확장 프로그램은 확인하지 못했습니다. 이는 검색 범위 내 결과이며 세계 최초라는 뜻은 아닙니다.

## 핵심 사용자 흐름

```text
과학·건강 뉴스 열기
→ 기사에서 연구 결과를 인용한 문장 자동 추출
→ DOI·논문 제목·저자 단서로 원 논문 탐색
→ 원 논문의 초록과 메타데이터 확보
→ 기사 문장과 논문 근거 문장을 1:1 비교
→ 과장 차원만 인라인 표시
→ 사용자가 원 논문과 기사 문장을 직접 열어 판단
```

## MVP 판정 유형

- `일치`: 기사 표현이 논문의 근거 강도를 넘지 않습니다.
- `상관→인과 과장`: 관찰 연구의 연관성을 원인·효과로 표현했습니다.
- `대상 확대`: 동물·세포·특정 표본 결과를 사람 전체 또는 다른 집단으로 확대했습니다.
- `효과 크기 과장`: 논문보다 효과의 크기·확실성을 강하게 표현했습니다.
- `한계 누락`: 논문의 핵심 제한 조건이 기사 결론에서 빠졌습니다.
- `검토 불가`: 원 논문 또는 대응 근거를 확인하지 못했습니다.

## 제품에서 제거할 기능

- 감정 44종 점수
- 기사 신뢰도 백분율
- 중립성·편향성 백분율
- 일반 주장 전체 팩트체크
- citation이 없는 초록·빨강 판정
- popup을 중심으로 한 결과 확인 흐름

## 재사용할 자산

- 뉴스 기사 DOM 추출
- 기사 문장 위치 매칭과 형광펜
- 스크롤 추적 tooltip 배치
- Gemini Interactions 완료 상태 검사
- 안전한 citation 링크 컴포넌트
- Vite + React + TypeScript + MV3 빌드 기반
- 기존 fixture와 브라우저 E2E 골격

## 새 기술 구조

```text
기사 DOM
→ 연구 인용 주장 추출
→ 논문 식별자 resolver
   1. 기사 링크·DOI·메타데이터
   2. Crossref 제목 검색
   3. Europe PMC 초록 검색
→ 연구 설계 구조화
   - study type
   - population/species
   - sample size
   - exposure/intervention
   - outcome
   - causal strength
   - limitations
→ 기사 주장과 논문 근거 span 비교
→ mismatch type + 양쪽 원문 span
→ 기사 안 인라인 evidence card
```

## 반드시 실패 폐쇄할 규칙

1. 원 논문을 특정하지 못하면 `검토 불가`입니다.
2. 논문 근거 span이 없으면 `일치` 또는 `과장`으로 확정하지 않습니다.
3. AI가 반환한 URL을 그대로 믿지 않고 Crossref/Europe PMC 메타데이터와 식별자를 확인합니다.
4. 기사의 각 판단은 하나의 기사 문장과 하나 이상의 논문 근거 span에 귀속돼야 합니다.
5. 전체 기사 신뢰 점수는 만들지 않습니다.
6. 일부 항목 실패가 전체 분석을 폐기하지 않도록 항목별 결과를 저장합니다.

## 4시간 Kill Test

본 개발 전에 기사-논문 쌍 5개로 다음을 확인합니다.

### 통과 조건

- 원 논문 식별 성공: 5건 중 4건 이상
- 원 논문 근거 문장 연결: 식별 성공 건의 80% 이상
- 사람이 미리 라벨링한 상관/인과·대상 확대 사례에서 심각한 오탐 없이 핵심 불일치 탐지
- 근거가 없는 사례를 `검토 불가`로 유지
- 한 기사 분석 데모가 심사위원에게 45초 안에 설명 가능

### 중단 조건

- 원 논문 자동 식별이 5건 중 3건 이하
- 기사와 논문 근거 문장 매핑이 반복적으로 실패
- citation 없이 확정 판정을 내려야만 데모가 성립
- 범용 Gemini에 기사와 논문 링크를 넣는 흐름보다 사용자 단계가 실질적으로 줄지 않음

Kill Test를 통과하지 못하면 이 피벗도 구현하지 않고 새 주제로 전환합니다.

## 구현 순서

### 1단계: RED/GREEN 최소 수직 슬라이스

1. 기사 주장과 논문 근거가 모두 있을 때 `상관→인과 과장`을 반환하는 실패 테스트를 먼저 작성합니다.
2. 근거 span이 없으면 반드시 `검토 불가`가 되는 실패 테스트를 작성합니다.
3. 최소 구현으로 테스트를 통과시킵니다.

### 2단계: 논문 resolver

1. DOI 직접 추출
2. Crossref 제목 검색
3. Europe PMC 초록 조회
4. 불확실한 후보는 자동 선택하지 않음

### 3단계: 인라인 UI

- 기사 문장을 클릭하면 popup이 아니라 기사 안에서 다음을 표시합니다.
  - 기사 표현
  - 논문 원문 근거
  - 연구 유형·대상·표본
  - 불일치 차원
  - 원 논문 링크

### 4단계: 기존 P0 보안 수정

- 모델 출력은 `innerHTML`이 아니라 `textContent` 기반 DOM으로 표시
- content script 권한을 지원 뉴스 도메인으로 축소
- Gemini 키는 `storage.local`에 두고 보안 한계를 안내
- 기사 전송 전 동의 표시
- 결과를 URL별로 분리 저장

### 5단계: 증거 수집

- 알려진 과장·비과장 사례 최소 10쌍
- 원 논문 식별률
- 근거 span 연결률
- 유형별 오탐·누락
- 인라인 하이라이트 성공률
- 일반 Gemini 수동 절차 대비 클릭 수와 소요 시간

### 6단계: 문서 재작성

코드와 실험 결과가 확정된 후에만 공식 DOCX를 다시 생성합니다. 측정하지 않은 수치는 쓰지 않습니다.

## 마감 전 병렬 필수 작업

- 참가자·팀·학교·연락처·보호자 동의·서명 작성
- 현재 Fact Lens 원본을 백업 브랜치 또는 태그로 보존
- 새 구현을 불변 커밋으로 공개 저장소에 반영
- 그 커밋에서 test·build·E2E·DOCX/PDF·ZIP 검증
